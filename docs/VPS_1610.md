# Развёртывание 1610 на VPS (локальная модель + туннель к ПК + Ollama)

Дата: 19.10.2026

## Архитектура

```
Интернет ──▶ nginx :8443 (1210, резерв) / :8444 (1610) ──▶ rtk1610-web :8001
                                                              │
                             ┌────────────────────────────────┤
                             ▼                                ▼
                  llama-server VPS :8080            127.0.0.1:11435
                  (Qwen-2B, слабая)                 (Ollama ПК, эмбеддинги)
                             ▲                                ▲
                             │ reverse-SSH-туннель            │
                  ┌──────────┴──────────┐                     │
                  │ ПК-агент (Windows)  │─────────────────────┘
                  │  -R 18080 → 8080    │
                  │  -R 18081 → 18081   │
                  │  -R 11435 → 11434   │
                  └──────────┬──────────┘
                             ▼
                  llama-server ПК :8080 (Qwen-9B, сильная)
                  Ollama ПК :11434 (nomic-embed-text-v2-moe)
```

## VPS

- Код: `/opt/rtk1610` (репозиторий `https://github.com/kykich/1610`, ветка `main`).
- venv: `/opt/rtk1610/.venv` (`mcp`, `pypdf`).
- Сервис: `rtk1610-web.service`, слушает `127.0.0.1:8001`
  (`MemoryMax=3G`, `KillMode=control-group`).
- **Слабая модель VPS работает всегда:** `llama-server.service`
  (`Qwen-2B`, `127.0.0.1:8080`) включён и запускается при загрузке.
  Она остаётся доступной независимо от действий пользователя.
- Сильная модель ПК запускается/останавливается из общего блока
  «Локальная модель» (через ПК-агент) и не является обязательной.
- Состояние: `/var/lib/rtk1610/session` (вне git).
- ENV: `/etc/rtk1610/rtk-web.env` (права 600).
- nginx: `/etc/nginx/sites-available/rtk1610` → HTTPS `8444`
  (тот же сертификат `/etc/ssl/rtk/rtk.crt`).
- ufw: открыты `22`, `8443`, `8444`.

### Единый блок «Локальная модель»

Один сценарий для VPS и ПК: **путь → «Сканировать» → выбор модели
внизу → настройки → «Запустить» / «Остановить»**.

- **VPS:** путь `/opt/models`. Слабая `Qwen-2B` уже работает всегда;
  блок показывает её состояние.
- **ПК:** путь `e:/Models/llama` (или другой путь на ПК). «Сканировать»
  идёт через ПК-агент; в списке появляются модели и `llama-server.exe`.
  «Запустить» запускает выбранную модель на ПК, поднимает туннель и
  переключает чат на `Qwen-9B`. «Остановить» завершает процесс на ПК,
  чат возвращается на всегда работающую `Qwen-2B`.

Отдельных кнопок «Сканировать папку ПК», «Поднять сильную модель»,
«Проверить ПК» больше нет — они дублировали этот блок.

## ПК (Windows)

1. Сильная модель: `llama-server.exe` на `127.0.0.1:8080`
   (`Qwen3.5-9B-Q6_K.gguf`).
2. Ollama: `127.0.0.1:11434`, модель `nomic-embed-text-v2-moe`.
3. ПК-агент из `G:\9potok\1610`:

```powershell
python -m rtk_pc_agent `
  --vps user@91.188.213.252 `
  --identity C:/Users/Gam/.ssh/ssh-key-9896 `
  --engine-port 8080 --tunnel-port 18080 --agent-port 18081 `
  --ollama-port 11434 --embed-tunnel-port 11435 `
  --root "E:\Models\llama" --embed-root "E:\Models"
```

Без `--no-confirm` на ПК появляется окно подтверждения (рекомендуется).
Для автоматического запуска без окна — добавить `--no-confirm`.

## Проверка

```bash
# снаружи
curl -sk https://91.188.213.252:8444/api/health
curl -sk https://91.188.213.252:8444/api/local
curl -sk https://91.188.213.252:8444/api/embed
curl -sk https://91.188.213.252:8444/api/rag

# на VPS (туннель)
curl -s http://127.0.0.1:18081/status
curl -s http://127.0.0.1:11435/api/tags
curl -s http://127.0.0.1:18080/v1/models -H "Authorization: Bearer $RTK_LOCAL_API_KEY"
```

Ожидаемо (RAG выключен):

- `/api/local`: `engine: weak`, `active_label: Qwen-2B`,
  `pc_alive` зависит от запущенной модели ПК;
- `/api/embed`: `runtime.running: true` (Ollama уже запущена треем),
  `reuse_offer.selected_model_present: true`, `POST {action:"start"}`
  возвращает `reused: true` и НЕ поднимает второй процесс;
- `/api/rag`: `enabled: false`, `embed_tunnel.error: "RAG выключен"`;
  обращений к Ollama нет;
- `POST /api/rag {action:"check"}` → `ok:false, "RAG выключен — Ollama
  не используется"`;
- `POST /api/rag {action:"reindex"}` → HTTP 409, индексация заблокирована;
- чат работает на `Qwen-2B`; `Qwen-9B` — после запуска модели ПК из UI.

## RAG и Ollama

RAG включается **вручную** чекбоксом «Использовать RAG». Движок эмбеддингов
выбирается в подблоке «Модель эмбеддингов (RAG)»:

1. путь `e:/Models` (ПК) или `/opt/models` (VPS) → «Сканировать»;
2. выбрать сервер `ollama.exe` и модель (embedding-модели идут первыми);
3. «Запустить».

**Reuse-first:** если Ollama уже запущена (трей `ollama app.exe` или вручную),
приложение предлагает использовать её и НЕ поднимает второй процесс. Внешняя
Ollama не останавливается кнопкой «Остановить» (кнопка только для процесса,
запущенного приложением).

Для доступа с VPS ПК-агент должен пробрасывать Ollama:
`--ollama-port 11434 --embed-tunnel-port 11435`. При `--ollama-port 0` порт
`11435` на VPS отсутствует, и блок покажет «туннель недоступен».

При выключенном RAG `/api/rag` не опрашивает Ollama; `/api/embed` обращается
к ней только по явным действиям пользователя (`scan`, `status`, `start`).

Выбранная модель/URL/размерность сохраняются в
`/var/lib/rtk1610/session/embed_model.json`; при смене модели требуется
переиндексация (UI покажет предупреждение `embed_mismatch`).

## Индексация RAG (только при включённом RAG)

```bash
sudo -u rtk sh /opt/rtk1610/deploy/index-rag.sh
# в фоне:
sudo -u rtk nohup sh /opt/rtk1610/deploy/index-rag.sh > /tmp/index.log 2>&1 &
```

Скрипт использует `docs_dir=/opt/rtk1610` и эмбеддинги через
`http://127.0.0.1:11435/api/embeddings`.
